### Согласованный план и контекст

Владелец прямо согласовал «конечно всё сделай» после предложения: редактирование на паузе, полное удаление черновика, удаление начатой политики из рабочего списка с остановкой новых выдач и сохранением истории/наград. Ветка root/server `codex/marketing-policy-lifecycle`: от свежего origin/develop с fast-forward `codex/segments-ux` (77e3ef5 server / 4066392 root); исходные деревья чистые, fetch выполнен. Новая фича зависит от ещё не слитой F01/UX; не интегрировать всё в develop без отдельного решения владельца. Режим обычный.

План: `Policy.deleted_at` + status paused, рабочий список исключает удалённые, отдельный фильтр «Удалённые» и read-only доступ к истории/отчётам. Новое право `marketing.delete`, администратор получает его через universal admin; manage-only роли не получают удаление автоматически. API delete проверяет expected revision, feature gate, scope и строковую блокировку. Hard-delete только никогда не запущенного draft без выдач; policy-owned FK данные очищаются в транзакции, глобальный audit остаётся. Начатые политики удаляются мягко с revision+1, evaluator/issue не должны продолжать работу по старой версии. Удаление в UI требует отдельного диалога и фиксирует id/revision при открытии.

Paused edit сохраняет baseline, историю, issued_count и policy/client/cycle dedupe. Охват/branch links и initial_mode после первого запуска фиксированы (владелец уведомлён); сегмент в том же scope, награда, текст, сроки, лимиты и исключения меняются для будущих выдач. Completed-baseline/all_current scan сбрасывается; незавершённый frozen future-only baseline продолжает прежний cursor. Старые промокоды проверяются по code.promotion_id, а не по новой награде policy. Для мягкоудалённых существующие карточки :show доступны пока награда/цикл актуальны, новые :send запрещены; сами выданные rewards не удаляются.

## Продуктовые решения

- Только completed заказы **везде**: количество, давность, выручка, новый цикл и актуальность предложения (последнее уточнение владельца 10 ноября). Незавершённые/отменённые не меняют цикл. Одна выдача policy/client/completed-order cycle; повторное завершение того же заказа не новый цикл.
- Установка = франшиза + филиалы. Настройки администратору; служебные группы руководителям своей области. Host feature flags только владельцу через CLI, не staff.
- Один общий bounded Background/Oban оркестратор; выключенное не создаёт необязательные данные/расчёты/ожидающие jobs. Суточные пересчёты допустимы. Original generation + job owner, canonical union gate locks, immutable source epochs защищают от старых попыток и off/on.
- Future-only замораживает eligible (client, cycle), включая паузу незавершённой подготовки. Issue/reward/notice атомарны. Сегменты независимы; изменение используемой группы требует актуальные impact/revision/confirmation.
- Notifications: in_app/Push/SMS; отдельная клиентская страница каналов. Маркетинговые согласия default false, SMS пока unavailable без провайдера. Core order/account Push независим. Карточки под хедером рядом с активным заказом, ручное закрытие per-device без отмены награды.
- Отчёт observational, явное окно, общие заказы dedupe, unknown не считать delivered. Historical bonus usage/cost per Issue неизвестен: ledger не хранит allocation debit→credit. Не выдумывать его по remaining. Production capacity не подтверждалась.
- F02/F05, полная F04, native apps, billing и production не входят.
