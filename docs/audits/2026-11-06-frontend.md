# Frontend audit — 2026-11-06

## Scope

The client source review directly read all 258 hand-maintained files under `client/src`: 240 module files and 18 files outside modules. Generated API/types and Swagger output, eight SVG/WOFF2 assets, and existing build output were excluded. Coverage by module: account 21, auth 19, branch 18, cart 19, franchise 12, fulfillment 35, menu 26, order 24, PWA 11, settings 4, shared 13, stock 14, widgets 24. Findings below are static traces from source review unless identified as tested; this pass did not reproduce the frontend issues in a browser.

## Findings

### F01 — Auth confirmation actions can race across attempts (medium)

`useCallConfirmation` does not consistently bind `start`, `submitCode`, and `dispose` completions to the active attempt. If an older request resolves after a new attempt or disposal, it can still update state. The auth modal invokes these actions from its current UI lifecycle, so the stale completion can affect a subsequent confirmation flow. See [`useCallConfirmation.ts`](../../client/src/modules/auth/composables/useCallConfirmation.ts:109) and [`AuthModal`](../../client/src/modules/auth/components/AuthModal.vue:47).

### F02 — Fulfillment storage retains a delivery address across logout (high privacy risk)

The fulfillment store persists its delivery address, while logout/session reset does not clear that persisted state. It is keyed by branch rather than account/session, so another user of the same browser can see or reuse the previous user's full address. Source trace: [`fulfillment.store.ts`](../../client/src/modules/fulfillment/stores/fulfillment.store.ts:13) and [`DeliveryPane`](../../client/src/modules/fulfillment/components/delivery/DeliveryPane.vue:42). This is a static data-flow finding; no browser account-switch test was run for it.

### F03 — Cart fetch and mutation responses can overwrite newer state (medium)

Cart store requests are not versioned or cancelled against later fetches/mutations. A slower earlier response can replace state produced by a newer user action. Relevant request paths are in [`cart.store.ts`](../../client/src/modules/cart/stores/cart.store.ts:35), including fetch and mutation handling.

### F04 — Cart component navigates to a non-existent catalog route (medium)

`CartComponent` links to route name `catalog`, while the router registers the menu route under a different name. The route target is therefore unresolved from the cart empty/error flow. Compare [`CartComponent.vue`](../../client/src/modules/cart/components/CartComponent.vue:47) and [`router`](../../client/src/router/index.ts:20).

### F05 — Delivery quote can remain stale during submit (high checkout correctness risk)

The delivery quote query keeps previous data while the branch/address inputs change. The order submit path can therefore continue using a quote computed for earlier inputs if the new quote has not arrived. Relevant paths: [`useDeliveryQuote.ts`](../../client/src/modules/fulfillment/composables/useDeliveryQuote.ts:23) and [`OrderForm`](../../client/src/modules/order/components/OrderForm.vue:103), including submit handling.

### F06 — Product card click target lacks keyboard activation (medium accessibility)

The product card interaction is click-driven without an equivalent keyboard-accessible control/activation path. Keyboard-only users cannot reliably open the product. See [`ProductCard.vue`](../../client/src/modules/menu/components/product/ProductCard.vue:15).

### F07 — Sidebar tile does not support Space activation (low accessibility)

The sidebar tile's keyboard handling omits the Space key behavior expected of its button-like interaction. See [`SidebarTile.vue`](../../client/src/modules/menu/components/SidebarTile.vue:8).

### F08 — Cart item async failures are not surfaced to the user (medium)

Cart item actions catch or absorb asynchronous failures without presenting an error state/message. The user may believe a quantity/removal change completed while the server rejected it. See [`CartItem.vue`](../../client/src/modules/cart/components/CartItem.vue:55) and cart action handling in [`cart.store.ts`](../../client/src/modules/cart/stores/cart.store.ts:121).

### F09 — Paused banner evaluates hours in the device timezone (low operational correctness)

The paused/availability banner uses device-local time rather than the selected branch's timezone. Around midnight or for branches in a different timezone, its message can disagree with branch operating hours. See [`PausedBanner.vue`](../../client/src/modules/branch/components/PausedBanner.vue:13).

## PWA behavior and limits

The service worker caches the application shell/static assets. The reviewed implementation does not provide offline menu/cart/order API data; offline behavior should be described as shell availability rather than offline ordering. This is a documented scope limit, not a finding that order submission is queued offline.

## Coverage and limitations

- Source inventory was read directly across all 258 hand-maintained client source files; generated outputs and binary assets were not included.
- The nine findings above were found by static tracing. They were not exercised through a browser or device test in this audit.
- `client` does not currently expose a `test:auth` check in CI; the local auth-isolation test command and broader validation results are recorded in [`2026-11-06-validation.md`](2026-11-06-validation.md).
- The client auth-session isolation fix is separately covered by PR #13. This report does not independently certify the fix's browser/socket behavior.
