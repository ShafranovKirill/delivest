## Воспроизведение

Использовать команды в [README](README.md). Для реальной demo-копии: запускать `scripts/menu-performance-server.exs` через `mix run --no-start`, только с локальной `DEV_DATABASE=delivest_menu_perf_*`; server всегда порт 4100. Nginx взять из nginx.client.conf, изменить listen на 3100 и upstream на 127.0.0.1:4100. Vite: VITE_PORT_WEB=3100 VITE_API_BASE_URL=http://localhost:4100; runtime env-config.js также должен указывать 4100. Старую сборку готовить из закреплённых исходных SHA.

Браузер: `node scripts/storefront-measure.mjs --url http://localhost:3100/demo-center --passes 5 --output artifacts/menu-performance/final --capture`. Первое открытие модалки: `node scripts/menu-modal-measure.mjs artifacts/menu-performance/final`. Генерация/quality: `MENU_MEDIA_OUTPUT=../artifacts/menu-performance/media mix run --no-start ../scripts/menu-performance-media.exs` из server с той же изолированной DEV_DATABASE.

Адресный UI с записями: `MENU_CAPTURE=1 pnpm --dir e2e exec playwright test --config playwright.menu-performance.config.ts --project=chromium --retries=0`. Для него отдельная заполненная `/e2e` база, DEV_S3_PORT=4100 и копирование четырёх файлов e2e/fixtures/menu-performance в server/priv/static/images как в workflow.

## Ограничения и следующий шаг

Данные относятся к локальному демо. Backfill в production не выполнялся. Возможен лишний S3-объект при удалении/замене исходника или сбое БД между успешным PUT и публикацией метаданных; битая ссылка не публикуется. Немедленный DELETE такого детерминированного ключа небезопасен для параллельного издателя; безопасная GC требует отдельного решения.

Всё сохранено локально; push, PR, merge, main и production не изменены. По команде «Пуш в Девелоп»: свежий fetch, проверка migration upgrade policy относительно последнего стабильного manifest, полный make preflight без PLAYWRIGHT_ARGS, PR и обязательные CI на финальном SHA.
