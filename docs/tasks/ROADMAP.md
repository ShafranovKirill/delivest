# Этапы и gates

Текущий шаг — [T00](phases/T00.md), затем блок S1 из [SESSION_PLAN](SESSION_PLAN.md). Статусы карточек — `planned`; `needs-verification` означает, что вывод аудита ещё нужно подтвердить на выбранном commit. Ни один этап реализации здесь не отмечен завершённым.

| Этап | Основной результат | Gate перед зависимыми изменениями |
| --- | --- | --- |
| [T00](phases/T00.md) | Короткий baseline SHA/status, audit pointers, test isolation и critical triage; F-карта инкрементально по блокам | Короткий checkpoint и приоритеты; подробная F-карта не gate до S1 |
| [T01](phases/T01.md) | D01–D04: ownership, каталог, стопы, cache | ADR до миграции shared rows; отрицательные роли, два филиала |
| [T02](phases/T02.md) | D05–D09: ACL, импорт, settlement, телефон, статистика | Проверены запись без права, конкурентная проводка и согласованность данных |
| [T03](phases/T03.md) | C01–C05: identity, адрес, auth, cart, quote | Приватность и корректный checkout; C01 пока лишь частично исправлено в источнике |
| [T04](phases/T04.md) | O04, R01, R08: CI, регрессия, auth, OpenAPI contract readiness | Gates запускаются на выбранных SHA; React Native не входит в scope |
| [T05](phases/T05.md) | R02, R06, R07: измерение, SQL, pricing, версии/cache | Сопоставимые before/after и регрессия заказа |
| [T06](phases/T06.md) | R03, R04, D10: durable effects и очереди | Повтор и отказ не теряют эффект и не создают дубль |
| [T07](phases/T07.md) | D11–D15, O09: адаптеры, сверка, capabilities | Неизвестный исход диагностируется, контракты проверены |
| [T08](phases/T08.md) | O01–O03, O05, O08: backup, release, secrets, maintenance | Восстановление, release runbook и проверка критичных env; O05 triage уже в T00 |
| [T09](phases/T09.md) | C06–C10: UX, a11y, TZ, честный offline | UI подтверждает реальные состояния и доступность |
| [T10](phases/T10.md) | R05: отдельный ADR/PR для async payment | Реализация только после решения о контракте; checkout API не меняется скрытно |
| [T11](phases/T11.md) | N01–N04, O06/O07: load, fault, pilot | Порог согласован до запуска; есть замеры и протокол пилота |
| [T12](phases/T12.md) | F01–F10: вертикальные функции | Для каждой функции выполнены её собственные зависимости и acceptance |

F04 event foundation планируется совместно с F01, при сохранении исходного бизнес-приоритета F01 → F10. F02, F03, полная F04, F05, F06 следуют затем; F07–F10 уточняются по пилоту. F06 диагностика проходит через интеграционные этапы. Критичные финансовые и privacy исправления T02/T03/O05 не ждут завершения длинной последовательности. Порядок таблицы не блокирует независимые ранние PR.

Для каждого проверенного PR: обновить доказательство, выбрать безопасную миграцию и обратимый rollout, выполнить проверки из репозитория и затронутых подмодулей, затем обновить [handoff](SESSION_HANDOFF.md) и [coverage](COVERAGE.md). Не объявлять исторические suite counts текущим запуском.
