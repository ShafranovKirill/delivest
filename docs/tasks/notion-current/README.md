## Ближайший согласованный объём

1. **Segments:** независимые ручные и динамические группы клиентов по сети/филиалам, мастер условий, подтверждение изменений затронутых политик.
2. **F01:** постоянные маркетинговые политики, исключения, мотивации через существующие промо/бонусы; одна выдача на период неактивности для каждой политики. Брошенная корзина сама по себе не запускает скидку.
3. **Notifications:** самостоятельный модуль SMS, Push и уведомлений под хедером витрины; закрытие карточки на устройстве не отменяет предложение.
4. **F04:** подробная воронка, рекламные ссылки и источники, аналитика каналов и покупателей, сводка франшизы, сравнение филиалов. Не выдавать связанную выручку за доказанный прирост.
5. **Оркестратор:** адаптивное выполнение тяжёлых расчётов с приоритетом заказов и платежей, справедливым распределением между организациями. После сбоя расчёт начинается заново, публикуется атомарно; устаревшие задания объединяются. Проблемы отображаются в панели администратора платформы.
6. **Feature Management:** отдельные переключатели крупных блоков; управление только администратором платформы, иерархия франшиза → ресторан → филиал. Выключенные функции скрыты и не запускают необязательные события/jobs. Массовые операции допускают частичный успех между организациями; зависимости включаются атомарно внутри объекта, отключение требует предупреждения и подтверждения. История сохраняется, повторное включение не запускает пропущенные рассылки.

**Изменение приоритетов:** F02 (отзывы) и F05 (рефералы) исключены из ближайшего этапа решением 7 ноября. F03 (слоты), F06 (подключение/диагностика), F07 (курьеры/маршруты), F08 (комбо/половинки), F09 (печать/связь), F10 (сохранённая оплата) этим решением не пересматривались. React Native — архитектурная готовность, само приложение не входит в рефакторинг.

Свежесть аналитики: продажи оперативно; воронка, ссылки и источники до 15 минут; тяжёлые расчёты до 24 часов. Агрегаты хранятся 36 месяцев; срок сырых событий ещё не согласован. Это целевые требования, не подтверждённые эксплуатационные показатели.

## Отдельный срочный backlog главной страницы

- ID организации во франшизе; происхождение показателя опоздания.
- Передача стоимости доставки в Frontpad.
- Явное отображение недоступных товаров в корзине вместо тихого удаления.
- Типовые промокоды, особенно первый заказ и автоматическое применение авторизованному клиенту.
- Статистика франшизы.
- Заказ по фактической зоне доставки вне выбранного города и поведение ограничения по зонам.
- Идеи: конструктор чеков, более гибкие настройки курьеров.

Эти пункты всё ещё отмечены открытыми в Notion; часть могла быть реализована последующими PR. Перед реализацией сверить с текущим кодом, не считать каждый пункт доказанным дефектом.

## Статус основы и оставшиеся решения

По отчёту 7 ноября кодовый объём S1–S5 завершён и слит. Старое ТЗ рефакторинга описывает состояние до этого отчёта. Открыты внешние provider/sandbox проверки, ручная screen reader проверка, эксплуатационная проверка секретов, длительные смешанные нагрузочные/fault прогоны и пилот. Утверждение отчёта об отсутствии production rollout относится к дате отчёта; текущий production здесь не проверялся.

Не согласованы все фильтры сегментов, детали мастеров и событий, часть правил зависимостей функций, срок сырых событий, оценки и порядок реализации модулей. Реализация функций этим сбором материалов не начата.
