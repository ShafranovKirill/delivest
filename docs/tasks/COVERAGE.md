# Покрытие исходных требований

Каждая строка указывает первичную карточку и единственный основной блок. Смежные блоки в [SESSION_PLAN.md](SESSION_PLAN.md) могут выполнять часть работы, но ID закрывается один раз по доказательству в primary task. `planned` — ещё не реализовано по этому плану; `needs-verification` — вывод аудита требует проверки на выбранном SHA; `implemented-local` — код проверен локально; сведения о merge указаны в строке или checkpoint, а внешние/эксплуатационные gates учитываются отдельно. `done` возможен только после merge, проверок и обновления статуса. Историческое «частично исправлено» C01 не равно `done`.
