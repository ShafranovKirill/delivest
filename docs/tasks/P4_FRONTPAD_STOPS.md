# P4 — стоп-лист Frontpad

Реализация: [server PR №45](https://github.com/ShafranovKirill/delivest-ex/pull/45). Основной commit `000173c5`, совместимость `1a782729`. Миграция `20261210000024` хранит durable состояние последнего успешного обновления отдельно от ошибок.

Frontpad обновляется ежедневно в 06:00 по актуальному часовому поясу филиала через registry P5, вручную со страницы интеграции и асинхронно после точного структурированного отказа заказа `{:frontpad, "invalid_product_keys"}`. Обычный Frontpad polling больше не вызывает HTTP; SQL-очистка старых стопов при отключённом sync сохраняется. Остальные провайдеры не меняют расписание. Неактивный storefront допускает настройку интеграции, удалённый филиал исключён.

Общий RefreshJob объединяет активные запросы независимо от причины. Cooldown — 60 секунд от попытки, максимум три попытки, timeout — 2 минуты. Результат и last-good счётчики сохраняются в SQL; ошибка не очищает действующие стопы. UI получает PubSub и сверяет состояние БД, пока запрос ожидается; discarded/cancelled/pruned jobs разблокируют действие через reconciliation. Повторный запрос не перезаписывает уже успешный результат состоянием running.

Отключение/смена интеграции удаляет только Frontpad stops без HTTP. После ответа провайдера повторно проверяются актуальные настройки, чтобы результат старого запроса не восстановил стопы после отключения. Сбой постановки refresh не меняет исходную классификацию ошибки заказа. Checkout не выполняет дополнительный HTTP, повторная отправка/оплата этой функцией не создаются.

Граница контракта: имеющаяся документация Frontpad подтверждает отказ `invalid_product_keys` для некорректного массива товаров, но не отдельный код «товар закончился». Это узкий подтверждённый product-key сигнал; произвольный stock-unavailable enum не выдуман. Успешный ответ с warnings.invalid_product_keys, сетевые/auth/другие ошибки обновление не запускают. Проверки с реальным провайдером не выполнялись.

Проверки: финальный feature `mix precommit` — 1520 тестов, 0 ошибок, 7 исключены; assets build прошёл. Главный агент независимо повторил 86 тестов без ошибок: расписание/TZ, manual ACL/UI, last-good, точный order trigger, dedup/cooldown, retry/terminal UI, отключение во время HTTP, legacy cleanup и остальные CRM пути. Объединённый P1–P7 `mix precommit` — 1542 теста, 0 ошибок, 7 исключены. На отдельной БД три новые миграции 22–24 применены, откачены и повторно применены без ошибок.
