## P2 — Раздел товарных операций · planned

Контекст: текущий [MenuExport](../../server/lib/delivest/net/menu_export.ex) и [UI товаров](../../server/lib/delivest_web/live/staff/product_live/products.ex) выгружают **CSV**, а не `.xlsx`. Импорт Excel локального каталога — новый процесс, отдельный от CRM MenuImport.

- [ ] Объединить в одном разделе три операции: экспорт Excel `.xlsx`, импорт Excel `.xlsx`, копирование товаров в другой филиал. Исходные товары при копировании остаются на месте.
- [ ] Определить явный шаблон и перечень полей для round trip; неизвестные/неподдерживаемые поля объяснять до применения. Сохранить совместимость существующей CSV-выгрузки.
- [ ] Для локального Excel-импорта сделать предпросмотр и валидацию: сопоставления, итоговые количества, ошибки. Для импорта и копирования дать по **каждому совпавшему товару в целевом филиале** выбор «пропустить» или «обновить»; неоднозначное совпадение требует явного решения пользователя.
- [ ] Спроектировать сопоставление по стабильным идентификаторам/SKU; не сливать товары молча по одному названию. При повторе импорта и копирования не создавать дубликаты.
- [ ] Безопасно переносить связи категорий, модификаторов и фотографий; учитывать цены, настройки целевого филиала и ACL. CRM ID при копировании не переносить.
- [ ] Ограничить размер файла и число строк, безопасно обрабатывать некорректный лист и формулы; показать прогресс и итог с ошибками по строкам.
- [ ] Проверить round trip, выборы по товарам, неоднозначные совпадения, повтор, права, целевой филиал и ошибки файла.

**Готово, когда:** все три операции доступны в одном разделе, предпросмотр позволяет осознанно применить изменения, а повтор не порождает дубликаты и не меняет другие филиалы.

## P4 — Стоп-лист FrontPad в 06:00 и по событию · planned

Контекст: [stop_poller](../../server/lib/delivest/integrations/crm/stop_poller.ex) использует общий интервал из [config.exs](../../server/config/config.exs), сейчас 600 секунд; [StopSync](../../server/lib/delivest/integrations/crm/stop_sync.ex) хранит последнее успешное состояние. Изменение относится только к **FrontPad**.

- [ ] Автоматически получать стоп-лист FrontPad ежедневно в **06:00 по часовому поясу филиала** с суточной идемпотентностью.
- [ ] Дать пользователю ручное действие «Обновить» с видимым результатом/ошибкой; ошибка сохраняет последнее успешное состояние.
- [ ] После **явного отказа FrontPad в заказе из-за недоступного товара** немедленно запускать асинхронное обновление стоп-листа. Не считать любой отказ поводом для обновления.
- [ ] Объединять одновременные запросы и ограничивать частые ручные нажатия/отказы; не блокировать checkout внешним запросом и не отправлять/списывать заказ повторно.
- [ ] Проверить локальные 06:00, ручное действие, ошибку с сохранением last-good, конкретный unavailable-product отказ, dedup/rate limit и отсутствие повторной оплаты/отправки.

**Готово, когда:** стоп-лист FrontPad обновляется по трём указанным поводам без влияния на остальные интеграции и безопасность заказа.
