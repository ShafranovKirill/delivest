# ADR: совместимость API и событий заказов

Дата: 2026-11-07. Автор решения: Codex, главный агент в рамках поручения владельца.
Статус: принято для R08 в текущем web/server scope.

## Контекст

Текущие HTTP routes, verbs, status, money и time поля используются web
клиентом и потенциально RN. Публичный OrdersChannel до этого отправлял
`{order, active}` без версии. Server domain events уже используют v1.
Менять или удалять текущие поля без окна совместимости небезопасно.

## Решение

- Текущий unversioned HTTP API считается v1. В этом изменении допускаются
  только additive поля; существующие routes, verbs и значения сохраняются.
- OrdersChannel добавляет `v: 1` к существующему payload без изменения
  `order` и `active`. Web принимает payload без `v` от legacy server,
  принимает `v: 1`, а при неизвестной версии не применяет данные события и
  инвалидирует identity-scoped orders queries для синхронизации через
  авторитетный HTTP API. Действующие session epoch guards сохраняются.
- v1 поддерживается без объявленного срока удаления. Breaking version
  требует отдельного явного решения владельца, версии контракта, проверки
  совместимости и согласованного окна миграции.
- RN lifecycle, хранение токена и device payload не входят в этот scope;
  окно совместимости RN не утверждено.

## Альтернативы и последствия

Без версии клиент молча применял бы будущий несовместимый payload.
Немедленная v2 API потребовала бы отдельного решения и migration window.
Выбранный вариант сохраняет старый сервер и позволяет web восстановиться
после неизвестного события. При неизвестной версии возможен дополнительный
HTTP запрос; если HTTP недоступен, данные останутся прежними до успешной
синхронизации.
