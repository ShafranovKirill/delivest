# Корзина: продолжение оптимизации

## Актуальное состояние — 19 ноября 2026

Продолжение находится в `codex/cart-completion` (root/server). Исходный checkpoint
`codex/storefront-bootstrap` сохранён; клиент остался на закреплённом `deaca40`.

- Удаление позиции, смена fulfillment и повтор заказа используют session-scoped
  команды с проверкой владельца под блокировкой строки корзины. Команда,
  ожидающая блокировку во время detach, возвращает непрозрачный `404` и не меняет
  товары или контекст. Внутренние unscoped API сохранены для служебных корзин.
- Checkout удерживает блокировку эпохи данных `FOR SHARE` до завершения своей
  транзакции. Смена эпохи ждёт commit; после смены старый revision отклоняется.
  Это добавляет один SQL-запрос checkout, финансовый алгоритм не ускорялся.
- Во время транзакции каталог акций и филиал могут читать готовый кэш; при
  промахе данные читаются напрямую через Repo без Courier и без публикации.
  Добавленные preload также не публикуются. Кэш корзины не записывается из
  внешней незавершённой транзакции; последующее чтение проверяет revision.
- Регрессии проверяют реальные независимые соединения, ожидание блокировки
  через `pg_stat_activity`, detach, смену эпохи, откат выбора подарков и
  добавления товара, а также конкурирующее списание общего баланса лояльности.

Во всех 7 сценариях совпали HTTP-статус, сумма, скидка, количество позиций и
код ошибки. Telemetry учитывает все процессы: в этом прогоне для корзины

сценарий подтверждает состав запросов, но не ускорение по времени или CPU:
параллельно выполнялись локальные тесты. BEGIN/COMMIT указаны отдельно;
снижение data SQL не означает такое же снижение всех обращений к БД.

Полный `make preflight`, полный E2E, push, PR и merge не выполняются до команды
«Пуш в Девелоп». Остальные пункты общего ТЗ перечислены в конце файла и этим
продолжением не закрываются.

## Что сохранено

- Основная ветка root/server/client: `codex/storefront-bootstrap`, исходный родитель `59c4d89` из develop; серверная база `df1b349b`, клиент `097a28b`.
- Завершённая реализация публичного/приватного bootstrap, кешей, пакетной загрузки филиалов и аналитики отделена от WIP корзины отдельным серверным коммитом.
- В WIP корзины: session-scoped команды добавления/замены/очистки и промокодов, cart-first блокировки, публикация кеша после commit, повторное использование уже прочитанных данных.
- Убрана глобальная очистка кеша всех корзин при изменении одной акции; используются версии каталога филиала. Полноту аудита импорта/переноса/восстановления требуется подтвердить при ревью.
- Добавлена миграция53: единственность строки data epoch. Эпоха читается в существующих SELECT корзины/версии и CartGuard и входит в непрозрачную cart_revision. Старый token должен отклоняться после смены эпохи, даже при совпавших catalog_version и составе. Совместимость клиентов без cart_revision сохранена.
- Повтор заказа начал переводиться на scoped-команду; эта последняя часть сохранена как черновик.

По последней команде пользователя при сохранении и push новые тесты/сборки/проверки не запускаются; это не зелёный релиз.

## Как продолжить на другом устройстве

Получить `origin`, открыть `codex/storefront-bootstrap`, выполнить `git submodule update --init --recursive`, прочитать root `HANDOFF.md` и этот файл. Все нужные серверные и клиентские коммиты закреплены gitlink родителя; не подменять подмодули произвольными tip их develop. Затем открыть рабочие ветки подмодулей `codex/storefront-bootstrap`, проверив совпадение HEAD с родительскими gitlink.

Скрипт `server/scripts/cart_sql_measure.exs` защищён allowlist имён одноразовых БД `delivest_f01_demo_perf_before_20261119` (схема50, исходный сервер df1b349b) и `delivest_f01_demo_perf_after_20261119` (схема53, новая версия). Эти БД существуют только на текущем устройстве; их содержимое не отправляется в Git. На другом устройстве сначала подготовить одинаковые фикстуры. Никогда не запускать профиль на пользовательской/production БД.
