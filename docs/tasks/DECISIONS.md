# Открытые решения

Решения фиксируются ADR до миграции или смены публичного контракта. Главный агент принимает обычные технические решения в согласованном scope и записывает обоснование; владельца привлекать для продуктовых, денежных или необратимых выборов, которые невозможно вывести из ТЗ.

| Область | Решение и момент |
| --- | --- |
| D01–D04 | Владелец Product/Category/Modifier/Tag/Client, installation-global и branch права; конфликтующие shared rows и cache invalidation. ADR до миграции T01. |
| D05–D09 | Capability импорта и sync; правила конкурентного settlement; владельцы телефонных данных и статистики. До соответствующего PR T02. |
| C01–C05 | Источник identity/session, адрес и согласие, branch cart, quote lifetime и авторизация. До PR T03. |
| R01/R08 | Границы домена и версия API для web/RN: текущий unversioned HTTP API считается v1, OrdersChannel additive `v: 1`, unknown v → HTTP resync. Breaking version только по отдельному решению владельца; RN lifecycle вне scope. [ADR](ADR-API-COMPATIBILITY.md). |
| R02/R06/R07 | Базовые метрики, единый расчёт цены, version/cache invalidation. Перед оптимизацией измерить исходное. |
| R03/R04/R05 | Durable effect и очередь; отдельно способ async payment, idempotency, unknown outcome и совместимость checkout API. R05 только отдельный ADR/PR. |
| N01–N04/O06/O07 | Порог активных сессий и ресурсов production, критерии latency/error/backlog, масштабирование и аварийные проверки. Согласовать до нагрузочного прогона. |
| F01/F04 | Согласие и каналы, сегменты/отмены, event taxonomy, сессия, атрибуция и retention. До кампаний и измерения. |
| F02/F03 | Срок и право доступа к отзыву; квота по времени готовности/получения, ASAP, hold/expiry и внешние каналы. До реализации. |
| F05/F06 | Определение нового клиента и обратной проводки; capabilities адаптеров, безопасный test order и разрешение unknown outcome. До пилота. |
| F07/F08 | Маршрутный провайдер/стоимость/критерий; формула цены половинок и передача состава в POS. До соответствующей вертикали. |
| F09/F10 | Модель принтера и подтверждения, граница полного офлайна; провайдер токенизации, seller scope, consent, refund и SCA. До аппаратного/платёжного пилота. |

Зафиксировать автора решения, дату, альтернативы, последствия, ссылку на ADR/PR и статус в следующем checkpoint. Ни одно значение здесь не является выбранной архитектурой.
