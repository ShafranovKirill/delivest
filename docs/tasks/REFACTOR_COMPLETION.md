## Открытые условия приёмки

1. **Completion code gate:** локальные server `mix precommit` **1447/0**, client auth/regression/build/lint, production-preview map target, сравнимый SQL benchmark и короткий load прошли. Перед merge проверить успешные Checks/E2E и review финального SHA через [root PR №25](https://github.com/ShafranovKirill/delivest/pull/25). R01 реализован локально и становится code-complete после поставки; R03/R04 сохраняют внешние проверки provider/очередей, R08 имеет реализованный кодовый контракт и ADR совместимости, RN-приложение вне scope. Полного эксплуатационного завершения эта ветка сама не доказывает.
2. **Provider и интерфейс:** sandbox CRM/fiscal/payment/push unknown outcome и ключей повторов; ручная screen reader проверка. Отсутствие учётных записей/стенда у этой сессии не превращается в успешный результат.
3. **Ops и нагрузка:** runtime secret inventory/rotation и старые логи; N02 warmup, 30-мин stable, spike, ≥2-часовой soak, три повтора с полной смешанной нагрузкой; pool saturation/backlog и production capacity; N04 fault recovery и pilot. Одиночная нода — текущая эксплуатационная предпосылка: O06 distributed cache/limiter становится gate при переходе к нескольким нодам.
4. **Отдельные решения:** R05 завершён ADR синхронной payment initialization; async реализация зависит от измерений и согласования lifecycle, не является обязательным условием текущего закрытия. Production rollout выполняется отдельно из `main` после release gates. React Native приложение и F01–F10 не входят в этот рефакторинг.
