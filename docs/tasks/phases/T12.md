# T12 — Вертикальные функции F01–F10

**Статус:** planned. **Источник:** [архив рефактора](../sources/refactor-spec.md), [архив функций](../sources/features-spec.md). **ID:** Все Fxx-Rxx/Fxx-Axx — по карточкам ниже.

## Цель и граница

UI/API/domain/storage/integration/tests функции; фактическую цепочку и границы проверять непосредственно перед своей вертикалью и записывать в MODULE_CONTEXT. Короткий T00 не выполняет полный аудит всех F.

## Зависимости и шаги

Нужные общие gates каждой функции; полный T11 не блокирует независимую F01.

Сохранять бизнес-порядок F01–F10. F04 event foundation выполнить совместно с F01; затем F02, F03, полная F04, F05, F06; F07–F10 по пилоту. F06 диагностика сквозная.

## Приёмка и доказательства

Для каждой функции выполнить все её Fxx-Axx из архивного ТЗ и связи каждого Fxx-Rxx в coverage; проверить web/API, права, повторы, отказы и данные.

## Миграция и откат

Каждая функция под feature flag/поэтапным rollout; миграция/откат и сохранение истории в её карточке.

## Следующий checkpoint

Выбрать связанную серию вертикальных карточек и проверяемые PR после зависимостей. После проверенного PR обновить [handoff](../SESSION_HANDOFF.md) и [coverage](../COVERAGE.md) с SHA, командами и реальными результатами.
