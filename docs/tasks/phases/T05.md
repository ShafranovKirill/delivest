# T05 — Критический путь, SQL и кеш

**Статус:** planned. **Источник:** [архив рефактора](../sources/refactor-spec.md), [архив функций](../sources/features-spec.md). **ID:** R02, R06, R07.

## Цель и граница

Server order/pricing/Ecto/catalog cache; замеры client/API на затронутом пути.

Основные блоки: R06/R07 → S1; R02 → S3. S1 даёт baseline и устраняет повторные чтения; транзакционный инвариант R02 принимает S3.

## Зависимости и шаги

T00 baseline; T01 ownership для общих версий кеша.

Измерить критический путь и повторный SQL, сохранить короткую транзакцию, единый расчёт цены, версии и инвалидацию меню. Менять только измеренный bottleneck.

## Приёмка и доказательства

Сопоставимые before/after p50/p95/SQL/ошибки с одинаковым профилем; регрессии сумм, branch isolation и concurrency. Исторический локальный benchmark не production capacity.

## Миграция и откат

Версии cache и схема заказа меняются с совместимым чтением; rollout/rollback и наблюдение устаревших данных.

## Следующий checkpoint

Связанные измеренные bottlenecks в одном доменном контексте, evidence в handoff. После проверенного PR обновить [handoff](../SESSION_HANDOFF.md) и [coverage](../COVERAGE.md) с SHA, командами и реальными результатами.
